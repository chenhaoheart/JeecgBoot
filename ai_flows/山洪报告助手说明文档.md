# 山洪报告助手 —— 使用说明与设计文档

> 版本：V1.1（2026-09-15，准确率增强：实测数据包/规则质检/跨章一致性/两阶段大纲）
> 所属模块：AI 应用平台 / 山洪灾害风险隐患调查报告自动生成
> 相关代码：后端 `jeecg-boot-module-airag`（`org.jeecg.modules.airag.shreport` 包）、前端 `jeecgboot-vue3/src/views/super/airag/shreport/`

---

## 1. 功能简介

「山洪报告助手」是一个**对话式 + 可视化面板**的 AI 应用页面，用于生成和管理《山洪灾害风险隐患调查评价报告》：

- **左侧对话区**：用自然语言向 AI 提需求，助手解析意图后自动调用对应的 AI 流程节点（总调度 / 单章子流程），无需手工填参数、无需打开流程设计器；
- **右侧章节面板**：7 个章节的生成状态（待审核 / 已通过 / 已驳回）、Markdown 内容预览、单章重新生成（可填修改意见）、逐章审核、全部通过后一键合并导出 Word。

整个业务围绕**批次号（batch_no）**管理：一次对话会话对应一个报告批次，可反复执行「生成 → 预览 → 驳回 → 带意见重生成 → 通过 → 导出」的闭环。

与「AI 应用管理」里的通用应用（智能体 / 高级编排）的区别：AI 应用是"聊天壳 + 单流程"，输出只在聊天气泡里；山洪报告助手是定制业务页面——对话是调度入口，具备多流程路由、章节状态机、审核流、Word 导出等业务能力。

## 2. 快速开始

### 2.1 前置条件

| 条件 | 说明 |
|---|---|
| 大模型 API Key | 在 **AI应用平台 → AI模型配置** 中给模型填入真实 Key 并「激活」。**接入智谱 GLM-4.7**：执行 `python ai_flows/setup_zhipu_model.py`（先 `$env:ZHIPU_API_KEY='你的key'`）幂等写入，模型代码 `glm-4.7`（付费），协议 OPENAI 兼容，BaseURL `https://open.bigmodel.cn/api/paas/v4`；随后在山洪助手页面顶栏「模型」下拉按会话选择（密钥只保存在模型配置中，页面接口不回传）。maxTokens 默认 4096；glm-4.7 有账户级速率限制（429/1302），意图解析失败会自动重试 1 次 |
| AI 流程已导入 | 库中应有 9 个流程（见 §5.3），状态 `enable`。若章节子流程缺少"章节落库"增强节点，执行 `ai_flows/upgrade_audit.py`（见 §7）；**V1.1 需再执行 `ai_flows/upgrade_data_packet.py`** 给 7 个子流程挂「实测数据包 sjbao / 写作提纲 tigang」入参与提示词引用。页面选择新模型时会按需自动创建「模型变体流程」，无需手工改流程 |
| 山洪数据源 | 数据源 `local_mysql2`（id `1999990000000000001`），SQL 节点从中读取 `ia_m_hsurface`、`prevention_object`、`road_culvert_bridge_dam`、`gully_occupy_area` 等调查表。V1.1 起后端在生成前额外按流域（`wscd`）组装「实测数据包」注入提示词，数据包查询逐表容错 |
| 后端已启动 | 新增类（Agent / 增强节点）需重新打包后端后启动；liteflow 流程注册在启动时加载，**直接改库中的流程设计后必须重启后端**才生效 |

### 2.2 入口

菜单：**AI应用平台 → 山洪报告助手**（URL `/super/airag/shreport/ShReportAssistant`，已开 keep-alive，切换页签不丢会话）。

## 3. 界面与操作

### 3.1 布局

```

│  助手: 进度：7/7 个章节已生成  │  │ ▸ 一、流域概况        [待审核]  │ │
│  助手: 已生成完毕，面板已更新  │  │ ▾ 三、外业调查成果    [已驳回]  │ │

└─────────────────────────────┴──────────────────────────────────┘
```

### 3.2 对话指令（自然语言，顺序无关）

| 你说 | 助手行为 |
|---|---|
| 「帮我生成 XX 流域的整份报告」 | 解析出流域名称 → 异步运行**总调度流程**（依次 7 个子流程），过程中每 60 秒推送一次进度，全部完成后自动刷新面板 |
| 「修改第三章：表格再细化，补充对象编码」 | 定位第 3 章 → 调用**单章子流程**，你的意见作为"补充资料（buochong）"注入提示词 → 完成后该章回到"待审核" |
| 「查看当前报告进度」 / 「生成好了吗」 | 直接按批次查库，回复各章节状态清单 |
| 「大崖沟成果报告摘要写了什么」 | 检索一期调查成果知识库（白龙江水系 4 条已入库报告），按检索片段回答 |
| 「导出 Word」 | 提示到右侧面板点击导出（需全部章节审核通过） |
| 其他闲聊 | 引导性回复 |

> 意图解析优先走大模型（结构化 JSON），模型不可用时自动降级为**规则解析**（关键词 + 正则），保证基础功能始终可用。

### 3.3 章节面板

- **批次号 + 查询**：切换/刷新指定批次的章节列表；
- **展开卡片**：预览该章 Markdown（表格、`【照片:编码】`占位符原样渲染）；
- **通过 / 驳回**：审核操作，驳回必须填审核意见（意见会显示在卡片上，并在「重新生成」时自动带入）；
- **重新生成**：弹出意见框 → 异步调用该章子流程 → 生成完成刷新后回到"待审核"；
- **导出 Word**：7 章全部"已通过"时才可点击，下载《山洪灾害风险隐患调查评价报告_批次号.docx》。

### 3.4 会话管理（多会话）

左侧「会话记录」侧栏支持**多会话并存与切换**，用于并行管理多份报告任务（如不同流域各一份）：

- **新建**：点侧栏标题栏 ➕ 或对话区「新对话」按钮，分配新的 conversationId + 批次号；
- **切换**：点击会话项，对话区消息与右侧章节面板**整体切换**到该会话的批次，互不串数据；
- **自动命名**：会话标题取首条用户消息（超 15 字截断）；生成中的会话带闪烁圆点标记；
- **归档/删除**：归档仅从主列表移入「已归档」，数据完整保留；归档视图里点🗑 才彻底删除（不影响数据库中已落库的章节，面板输入批次号仍可查询）；
- **刷新同步**：点侧栏标题栏⟳ 以服务端为准强制对账——库里（或其它窗口）删掉的会话立即消失；底部「清除本机缓存」可强制丢弃本机记录并按服务端重新恢复（内置浏览器/webview 常驻时缓存不会被自动清理，是不同步的常见来源）；
- **持久化**：服务端 `sh_report_agent_session` 为权威源（按登录名维度，与后端 `currentUserKey()` 一致），localStorage 仅作降级缓存（key `shreport_agent_sessions__<username>`，旧版 `<userId>` key 自动迁移）；同步失败时页面会明确提示"当前显示的是本机缓存数据"，不会静默拿缓存糊弄。旧版单会话 sessionStorage 数据自动迁移；相邻重复消息自动去重。

隔离机制（各报告任务不混乱的保证）：

| 层 | 机制 |
|---|---|
| 会话 | 后端上下文按 conversationId 隔离，各自记住批次号/流域名/对话历史 |
| 数据 | 章节落库、审核、重生成、导出全部按 batch_no 过滤 |
| 执行 | 流程异步执行携带各自 batch_no，SSE 事件按会话推送；后台完成的会话**不会劫持**当前查看的另一个会话的面板 |
| 前端 | 消息数组按会话捕获写入，流式回复期间切换会话不串写；localStorage 按用户隔离 |

注意：同一时刻仅允许一个会话进行 AI 请求（发送按钮全局置灰），避免并发流式响应交叉。

## 4. 典型工作流

```
① 打开页面 → 输入「帮我生成XX流域的整份报告」
② 等待生成（对话区实时显示进度），右侧面板出现 7 章，均为"待审核"
③ 逐章展开预览 → 满意点「通过」；不满意点「驳回」并填意见
④ 对「已驳回」章节，可在对话里说「修改第三章：<意见>」，或点卡片「重新生成」
⑤ 7 章全部「已通过」→ 右上角「导出 Word」下载正式报告
```

## 5. 技术设计

### 5.1 总体架构

```
浏览器页面 ShReportAssistant.vue
 ├── AgentChat.vue（对话区）
 │     └─ fetch SSE ──► POST /sh/report/agent/chat/send
 ├── ChapterPanel.vue（章节面板）
 │     ├─ GET  /sh/report/chapter/list      （查章节）
 │     ├─ POST /sh/report/chapter/audit     （审核）
 │     ├─ POST /sh/report/chapter/regenerate（单章重生成）
 │     └─ GET  /sh/report/chapter/download  （导出 Word）
 └─ SSE 事件联动：收到 refresh 事件 → 面板自动 reload

后端 ShReportAgentController / ShReportAgentService
 ├── ① 意图解析：AIChatHandler 调大模型，输出意图 JSON（失败降级规则解析）
 ├── ② 路由执行：GENERATE_ALL → 总调度流程；GENERATE_CHAPTER → 对应子流程
 │     （意见注入 buochong；第7章自动注入前6章内容 ch1~ch6）
 ├── ③ 异步执行：IAiragFlowService.runFlow(线程池) + 轮询 sh_report_chapter 等落库
 └── ④ SSE 推送：text（回复文本）/ refresh（刷新面板）/ error / done

AI 流程引擎（liteflow，jeecg-aiflow-boot4）
 ├── 章节子流程×7：start → sql×N（山洪数据源取数） → llm → enhanceJava(章节落库) → end
 │     失败降级：CATCH → end-fb（系统默认框架文案，不落库）
 ├── 总调度流程：start → (subflow→CATCH兜底sql)×7 → end（拼接完整报告）
 └── 合并导出流程(09)：start → enhanceJava(reportWordExportEnhance) → end
```

### 5.2 SSE 事件协议（`/sh/report/agent/chat/send` 与 `/sh/report/agent/outline/confirm`）

| event | data | 说明 |
|---|---|---|
| `text` | 文本（Markdown） | 助手回复，前端按 `\n\n` 追加渲染 |
| `refresh` | batchNo | 章节状态有更新，前端刷新右侧面板 |
| `progress` | `{chapterNo,status,message,batchNo}` | 章节级进度（生成中/待审核/失败），前端乐观更新卡片 |
| `watershed` | `lybm\|lymc` | 会话已绑定流域，前端同步面板下拉与对话顶栏 |
| `choose` | `[{lybm,lymc}]` | 多个同名/相近流域候选，前端渲染点选按钮，点击回发「确认使用流域：名称\|编码」 |
| `outline` | 7 章提纲 JSON 数组 | 两阶段生成的提纲，前端弹大纲确认窗 |
| `download` | `batchNo\|lybm` | 对话内导出指令，前端直接拉取 Word |
| `error` | 错误描述 | 异常提示（流继续，以 done 结束） |
| `done` | ok | 本轮结束信号（前端收到后结束读取） |

意图解析 JSON 结构：`{"action":"GENERATE_ALL|GENERATE_CHAPTER|QUERY_STATUS|EXPORT|PREPARE_OUTLINE|CHAT", "chapterNo":1-7或null, "wsmc":"流域名称", "requirement":"用户补充要求", "reply":"给用户的回复"}`。意图模型 temperature 固定 0，输出经 Schema 校验（action 枚举、chapterNo 1-7），非法时携带原因自动重试 1 次再降级规则解析。

### 5.2.1 V1.1 准确率机制

| 机制 | 实现 |
|---|---|
| 实测数据包 | `ShReportDataPacketService` 按 `wscd` 单表容错查询（断面信息/对象分类/乡镇/重点对象），生成 Markdown 数据包作为流程入参 `sjbao`，提示词约束「只能使用数据包，缺失写暂无调查数据，严禁编造」 |
| 两阶段大纲 | 说「先出大纲」→ 意图 `PREPARE_OUTLINE` → 推送 `outline` 事件 → 前端勾选确认 → `POST /agent/outline/confirm` 放行暂存动作；提纲作为入参 `tigang` 分章注入。大纲为**可选旁路**，不确认也可一句话直出 |
| 规则质检闸门 | `ShReportQualityChecker`：阻断级（占位符 XX/TBD/待补充、篇幅过短、Markdown 表格崩坏）自动带问题清单重生成 1 次；提示级（百分数>100、关键计量负值、未提及目标流域、1/3/4/6 章缺表格）写入质检问题表与章节提示。阈值 `shreport.qc.min-length`（默认 200）可配 |
| 关键指标 | `ShReportMetricService` 将对象数/人口（数据源）与首章抽取的面积/河长/比降/高程锁定到 `sh_report_metric`，作为全报告基准 |
| 跨章一致性 | 全部章节完成后 `ShReportConsistencyChecker` 比对各章指标取值与基准值，矛盾写 HINT 级问题（挂第 7 章）并在对话推送摘要，只提示不阻断导出 |
| 版本保留 | 重新生成时旧稿写入 `content_prev`，前端「对比上一版」做行级 LCS 差异；面板支持「在线编辑」（保存后回待审核） |
| 第4章参数 | 原写死在流程 SQL 的 Q/n/S 改为配置 `shreport.ch4.design-peak-flow/roughness/slope`，经数据包与提示词约束 LLM；SQL 节点内常量仍建议在流程设计器中同步替换 |
| 页面模型切换 | 对话顶栏可选择已激活的聊天模型（如智谱 glm-4.7），选择按会话持久化：意图解析直接用该模型；章节生成自动创建「模型变体流程」（流程名 `原流程名#M<modelId后8位>`，仅替换 LLM 节点 modelId，首次使用按需创建、之后复用），不修改原流程 |

### 5.5 配置项

```yaml
# application-dev.yml
shreport:
  agent:
    model-id: '1897481367743143938'   # 意图解析/大纲润色使用的模型ID，留空用系统默认模型（意图解析温度固定0）
  qc:
    min-length: 200                   # 章节最小字数，低于视为阻断级「篇幅过短」
  ch4:
    design-peak-flow: 30              # 第4章设计洪峰流量 Q(m³/s)
    roughness: 0.035                  # 沟道糙率 n
    slope: 0.01                       # 沟道比降 S
```

## 8. 多标签页与并发防护

多个浏览器标签页同时使用助手、或同一报告并行触发多个生成任务时，有两层防护（V1.2 新增）：

**① 章节写入互斥（后端 `ShReportBatchLock`）**

- 生成任务按「批次号 + 流域编码」加互斥锁：Redis `setIfAbsent` 原子加锁，持锁上限 4 小时兜底（防 JVM 崩溃死锁），Redis 不可用时降级为本机内存锁；
- 同一批次同一流域：对话生成进行中，另一个页面/入口再触发整份生成或单章重新生成 → 立即拒绝并提示"该批次该流域已有生成任务正在进行"，避免章节"先删后写"被交错覆盖；
- 被拒绝的重新生成请求只记日志，**不会**用失败占位覆盖已有章节内容；对话入口被拒时通过 SSE error 事件提示用户；
- 不同流域（同批次）互不影响，可并行生成；任务结束（含异常/取消）在 finally 中释放锁。

**② 会话存储合并（前端 `useReportSession.saveStore` / `mergeServerSessions`）**

- 服务端 `sh_report_agent_session` 为权威源；localStorage 是降级缓存，进入页面时先恢复缓存再与服务端并集（按 conversationId、按消息时间取并集，不整段覆盖）；
- 本机保存走"读-合并-写"：以 conversationId 为键取并集，同一会话取 `updateTime` 较新的一份。效果：A 页新建的会话不会被 B 页（内存还是打开时的旧快照）的下一次保存抹掉，消息不丢；
- **删除传播**：进入页面/点⟳ 刷新时以服务端为准做权威裁剪——远端已确认不存在的本地会话一律移除并落墓碑，库里手工删掉的会话不会在界面上"死而复生"；推送失败尚未入库的会话（`pending` 登记）会被保护，不会被误删；
- **实时同步**：窗口聚焦/可见性变化/每 30 秒（后台标签兜底 120 秒）拉一次服务端合并，同浏览器多标签通过 `storage` 事件即时并入。注意 IDE 内置浏览器（webview）的 `document.hidden` 常长期为 true 且焦点事件不触发，故不再以 hidden 作为跳过条件，否则内置浏览器会永远不对账；
- **拉取失败不静默**：失败时提示"当前显示的是本机缓存数据"，且不给服务端查不到的会话抬高推送水印，网络恢复后的变更仍能补推（否则故障期间的对话永久丢失）；
- **删除墓碑（服务端）**：删除接口打 Redis 墓碑（`shreport:del:<user>:<conv>`，7 天），`saveTurn` 与 `/sessions/save` 落库前先查墓碑——删除瞬间正在跑的对话轮次结束时不会把会话 upsert 回库复活。
- **推送水印只抬到远端时间**：合并后抬 `merged.updateTime`（= max(本地,远端)）等于宣布"本地超集已入库"，会让上次推送失败留下的消息永远不再补推；因此水印只认服务端已确认拥有的时间。
- **元数据按时间仲裁（后端）**：消息永远并集，但标题/流域/模型/归档标记按 `updateTime` 新者胜——陈旧写入（`incomingTs < oldTs`）会主动清空这些字段交给 `COALESCE` 保留库中原值，避免"旧快照取消归档、把新标题改回旧标题"。
- **账号切换自愈**：会话 store 是模块级单例，页面走 keep-alive（登出不销毁组件）。监听登录人变化，清空内存会话与删除/推送集合后按新用户重新恢复，避免把上一用户的会话显示给新用户。

## 10. 已知限制与 FAQ

| 项 | 说明 |
|---|---|
| 模型 Key 为占位符 | 当前 AI模型配置中的 Key 均为示例值，真实生成必须先配置有效 Key；未配置时意图解析降级为规则匹配，流程 LLM 失败章节标记「失败」并可重新生成 |
| 会话持久化 | 上下文存 Redis（降级内存），重启后可恢复批次/流域/待执行动作；对话历史保留最近 20 条 |
| vite 代理下 SSE 不关闭 | 开发代理不转发流结束信号，前端用「done 事件 + 8 秒空闲看门狗」兜底；生产 Nginx 需对该接口 `proxy_buffering off` |
| 照片占位 | 章节内容中 `【照片:编码】` 仅作占位，需按编码映射本地照片后再渲染（可在 Word 导出器中扩展） |
| 影响分析参数 | Q/n/S 已配置化（`shreport.ch4.*`，经数据包注入提示词）；流程 SQL 节点内历史常量建议在流程设计器中同步替换 |
| 质检为规则检查 | 当前质检不调用大模型，以规则/数值校验为主；跨章一致性只提示不阻断，宁漏勿滥避免误报 |
| 一期调查成果知识库 | 正文在 MySQL `airag_knowledge_doc`，向量在 Docker pgvector（**5433** / `vector_db.embeddings_2048`）。流程说明见 [`山洪调查成果知识库与向量化说明.md`](./山洪调查成果知识库与向量化说明.md)。未装 pgvector 时助手回退关键词检索。 |
| code 节点不可用 | aiflow 设计器 3.9.5-beta 的脚本节点有渲染 bug，统计/公式一律放在 SQL 节点内实现 |
